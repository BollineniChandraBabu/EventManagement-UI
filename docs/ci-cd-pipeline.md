# CI/CD Pipeline

## 1. Current pipeline

Two GitHub Actions workflows, both generated by the Firebase CLI.

### 1.1 Pull request — preview

`.github/workflows/firebase-hosting-pull-request.yml`

```yaml
name: Deploy to Firebase Hosting on PR
on: pull_request
permissions:
  checks: write
  contents: read
  pull-requests: write
jobs:
  build_and_preview:
    if: ${{ github.event.pull_request.head.repo.full_name == github.repository }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm run build
      - uses: FirebaseExtended/action-hosting-deploy@v0
        with:
          repoToken: ${{ secrets.GITHUB_TOKEN }}
          firebaseServiceAccount: ${{ secrets.FIREBASE_SERVICE_ACCOUNT_CHANDU_GOLDENGREETINGS }}
          projectId: chandu-goldengreetings
        env:
          FIREBASE_CLI_EXPERIMENTS: webframeworks
```

### 1.2 Merge to `main` — live

`.github/workflows/firebase-hosting-merge.yml`

```yaml
name: Deploy to Firebase Hosting on merge
on:
  push:
    branches:
      - main
jobs:
  build_and_deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm run build
      - uses: FirebaseExtended/action-hosting-deploy@v0
        with:
          repoToken: ${{ secrets.GITHUB_TOKEN }}
          firebaseServiceAccount: ${{ secrets.FIREBASE_SERVICE_ACCOUNT_CHANDU_GOLDENGREETINGS }}
          channelId: live
          projectId: chandu-goldengreetings
        env:
          FIREBASE_CLI_EXPERIMENTS: webframeworks
```

## 2. Pipeline stages (as implemented)

```
checkout → npm ci → npm run build → deploy (preview or live)
```

| Stage | Present | Notes |
| --- | --- | --- |
| Install | Yes | `npm ci` |
| Lint | **No** | No ESLint config exists |
| Unit tests | **No** | `karma.conf.js` missing |
| Build | Yes | Production configuration |
| Bundle budget check | Yes | Fails the build on breach |
| Deploy | Yes | Firebase |
| Smoke test | **No** | Manual after deploy |
| Security audit | **No** | `npm audit` not run |

## 3. Gaps and recommended pipeline

### 3.1 Recommended workflow

```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

jobs:
  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run lint            # once ESLint exists
      - run: npx ng test --watch=false --browsers=ChromeHeadless --code-coverage
      - run: npm audit --audit-level=high
      - run: npm run build
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: coverage
          path: coverage/
```

Then a separate deploy job that depends on `quality`.

### 3.2 Ordering and gating

1. Install
2. Lint (fast feedback)
3. Unit tests
4. Build (catches type and budget errors)
5. Security audit
6. Deploy preview (pull requests) or live (main)

Deployment must not run if quality fails. Add `needs: quality` to the deploy job.

## 4. Secrets

| Secret | Used by | Purpose |
| --- | --- | --- |
| `FIREBASE_SERVICE_ACCOUNT_CHANDU_GOLDENGREETINGS` | Both workflows | Deploy to Firebase |
| `GITHUB_TOKEN` | Both workflows | Comment on the PR, report the preview URL |

Never add API keys or user credentials to the repository. See
[`secrets-management.md`](secrets-management.md).

## 5. Branching model

| Branch | Purpose |
| --- | --- |
| `main` | Deployable; every merge deploys to live |
| `feature/*` | Work in progress; PR into `main` |
| `fix/*` | Defect fixes; PR into `main` |
| `hotfix/*` | Urgent fixes; PR into `main`, release immediately |

There is no long-lived `develop` branch. Keep `main` releasable.

## 6. Pull request requirements (recommended)

- [ ] One approval.
- [ ] CI quality job green.
- [ ] Preview URL reviewed.
- [ ] No unrelated changes.
- [ ] Changelog entry for user-visible changes.
- [ ] Screenshots for UI changes.

## 7. Caching and speed

| Optimisation | Effect |
| --- | --- |
| `actions/setup-node` with `cache: npm` | Reuses the npm cache |
| `npm ci` | Faster and reproducible |
| Build artefact reuse | Deploy the exact artefact that was tested |

A clean install plus production build typically takes a few minutes; tests add time depending on
the suite.

## 8. Failure handling

| Failure | Action |
| --- | --- |
| Install fails | Check the lockfile and registry access |
| Build fails on types | Fix the error; do not bypass `strict` |
| Build fails on budget | Lazy-load the offending dependency or justify a budget change |
| Test fails | Fix the code or the test; never merge red |
| Deploy fails on auth | Verify the service-account secret and project id |
| Deploy fails on config | Check `firebase.json` and the build output path |
